## Summary
The original source of the technical debt metaphor. Cunningham describes how shipping code that is not fully understood creates a debt whose interest is paid in the form of extra effort required to make future changes.

## Key Arguments
- Technical debt is not inherently bad, it can be a deliberate trade-off to ship faster
- The "interest" on debt is paid every time the system is modified without first restructuring
- Debt should be repaid as understanding matures

## Key Concepts
- Technical debt metaphor (principal + interest)
- Deliberate vs inadvertent debt
- Refactoring as debt repayment
